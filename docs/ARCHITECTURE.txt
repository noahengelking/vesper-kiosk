3. SERVICES AND THEIR RESPONSIBILITIES
================================================================================
SYSTEM SERVICES
---------------
desk-dashboard.service
  Unit file: /etc/systemd/system/desk-dashboard.service
  ExecStart: /usr/bin/python3 /home/<kiosk-user>/dashboard/server.py
  Runs as:   user
  Listens:   127.0.0.1:8080
  Role:      Main dashboard HTTP API and static index.html server.
             Talks to Spotify, calendar sources, LRCLIB, local system tools,
             and the user-level kiosk service when a Chromium restart is asked.
  Restart:   always, 2 seconds

ssh.service
  Role: remote administration. Bound to the machine's LAN address.

wpa_supplicant.service
  Role: current Wi-Fi connection and saved network management.
  Current config: /etc/wpa_supplicant/vesper.conf

user@1000.service
  systemd user manager for UID 1000. Hosts the user-level services below.

USER SERVICES
-------------
vesper-kiosk.service
  Unit file: ~/.config/systemd/user/vesper-kiosk.service
  Role: launches and supervises the Chromium kiosk.
  Startup: waits for the Wayland socket, then starts Chromium with kiosk,
           autoplay, Wayland, GPU rasterization and reduced-background flags.
  Restart: always, 2 seconds
  Enabled: yes, at default.target

desk-audio.service
  Unit file: ~/.config/systemd/user/desk-audio.service
  ExecStart: /usr/bin/python3 /home/<kiosk-user>/dashboard/audio_server.py
  Listens: 127.0.0.1:8081
  Role: controls PipeWire/PulseAudio sinks and volumes for the dashboard.

auto-output.service
  Unit file: ~/.config/systemd/user/auto-output.service
  ExecStart: /usr/bin/python3 /home/<kiosk-user>/dashboard/auto_output.py
  Role: prefers the 3.5 mm output when a jack is connected.

soloist.service
  Unit file: ~/.config/systemd/user/soloist.service
  Role: exposes Vesper as a Spotify Connect device named "Vesper".
  Credentials are in ~/.config/desk-dashboard/soloist.env.

Sway and trackpad
-----------------
Sway is the Wayland compositor. The Sway config is:
  ~/.config/sway/config

Sway starts:
  - vesper-kiosk.service (via systemctl --user start)
  - a supervised trackpad.py loop
  - normal Sway/audio user services through systemd

The trackpad.py loop is kept outside systemd because it is tied directly to
the active graphical session.

4. NETWORK PORTS AND BOUNDARIES
================================================================================

127.0.0.1:8081   Local audio control server (audio_server.py)

The dashboard and gesture APIs are intentionally bound to localhost. They are
consumed by the Chromium kiosk and not exposed directly to the LAN.

5. FILE MAP
================================================================================
/home/<kiosk-user>/dashboard/index.html
  Single-page frontend. Contains the dashboard UI, CSS, main JavaScript,
  the bundled local QR encoder, and the trackpad gesture integration script.

/home/<kiosk-user>/dashboard/server.py
  Main Python backend. Serves index.html and APIs. Handles:
    - Spotify OAuth token refresh and Web API calls
    - single-flight request coalescing and short caching
    - lyrics lookup through LRCLIB
    - calendar refresh and event expansion
    - Wi-Fi scan/join and Wi-Fi credential lookup for the guest QR
    - brightness, power, SSH, battery and network status
    - system health metrics and Chromium restart
    - static HTML delivery

/home/<kiosk-user>/dashboard/audio_server.py
  Local audio helper for PipeWire/PulseAudio sink enumeration, choosing the
  default output and setting volume.

/home/<kiosk-user>/dashboard/auto_output.py
  Automatically picks the 3.5 mm jack when connected.

/home/<kiosk-user>/dashboard/trackpad.py
  Reads the raw touchpad event device, recognizes taps, two-finger taps,
  one-finger slides, three/four-finger swipes, edge drags and corner actions,
  then streams JSON gesture events to Chromium through SSE on port 8099.

/home/<kiosk-user>/dashboard/config.json
  Spotify application client ID.

/home/<kiosk-user>/.config/desk-dashboard/spotify.json
  Spotify OAuth tokens. Written by the token refresh/login flow.

/home/<kiosk-user>/.config/desk-dashboard/calendar.urls
  One or more calendar ICS URLs used by the backend calendar refresh loop.

/home/<kiosk-user>/.config/desk-dashboard/soloist.env
  Soloist Spotify Connect API key/environment.

/home/<kiosk-user>/.config/sway/config
  Sway setup: keyboard layout de, maintenance keybinds, hides cursor,
  starts the kiosk service and the trackpad loop.

/home/<kiosk-user>/.config/systemd/user/*.service
  User services: vesper-kiosk, desk-audio, auto-output, soloist,
  soloist-update and related timers.

/etc/wpa_supplicant/vesper.conf
  Saved Wi-Fi networks. The guest QR reads the current SSID's PSK from this
  world-readable local file; it never sends the password to a third party.

/home/<kiosk-user>/.config/chromium/
  Chromium profile, local storage, cache and session state.

MAIN OVERLAYS
-------------
Focus screen:
  Large countdown, tap anywhere to end focus. Focus remains visible in the
  clock tile's badge while active.

Lyrics screen:
  Album art, track metadata, synced lyric lines.
  Current line is white and larger.
  A full-width song progress bar runs along the top edge, with elapsed/total
  time at the upper right.
  The top touchpad edge seeks the song while lyrics are open.
  The right touchpad edge controls Spotify volume and shows a temporary
  vertical volume bar on the lyric screen.
  Two-finger tap pauses/plays without leaving the lyrics screen.
  Swipe up/down or use two-finger scrolling to scroll manually for 8 seconds.
  Top-left/top-right corners change tracks while lyrics remain open.
  Tap anywhere closes lyrics.

Morning brief:
  Greeting, date, weather, first event, current music, AQI, recommendation and
  a deterministic local fun fact of the day.
  Auto-shows once per day between 04:00 and noon when enabled.
  Can be triggered for testing from Settings -> Appearance -> Test morning brief.
  Tap anywhere dismisses it.

Health screen:
  Read-only system cards for host, uptime, load, memory, disk, CPU temp,
  Chromium process count/RSS, kiosk state and dashboard state.

Guest screen:
  Large welcome, local time, weather, Wi-Fi SSID.
  Animated colour blobs drift in the background.
  A locally generated Wi-Fi QR appears in the bottom-right corner.
  Single-finger tap toggles Spotify playback.
  Four-finger swipe up exits guest mode.
  Guest mode exits automatically when its timer expires.

Idle screen:
  Minimal large clock, date and current weather after the configured idle
  delay. Any input wakes it.

COLOUR AMBIENCE
---------------
Album colours are extracted from the album art when possible. The colours are
applied to:
  - the Spotify tile background
  - a whole-display tonal glow layer
  - the lyrics screen background
Ambience intensity is stored as ambientLevel (0-100). Zero turns there off.

DAY RIBBON
----------
Optional full-width 24-hour strip fixed directly to the top edge of the
display. It spans the entire viewport width and does not occupy the clock
tile. The battery indicator overlays the right end of the same top line.
The Time / swipe-to-switch label sits below the strip.

The strip shows:
  - timed calendar events as blocks
  - all-day events as a thin sliver
  - sunrise and sunset markers
  - a live now marker
Hidden by default and toggled from Settings home or Appearance.

GESTURE SUMMARY
---------------
Three-finger swipe:
  Moves keyboard-style focus between the four dashboard tiles.

Four-finger swipe down:
  Opens Settings.

Four-finger swipe up:
  Closes the current overlay or exits guest mode.

One-finger horizontal slide:
  Clock tile: cycles the highlighted clock.
  Calendar: moves the selected day.
  Lists/pickers: right opens a playlist, left goes back/closes.

One-finger vertical slide:
  Calendar: moves a week.
  Lyrics overlay: scrolls lyrics manually.
  Keyboard: moves the highlighted key.
  Lists: steps through entries.

Two-finger tap:
  Play/pause Spotify in normal dashboard mode.
  Ignored while an overlay is active, with guest mode using single tap.

Two-finger vertical scroll:
  Settings: moves between rows.
  Lists/pickers: scrolls the list.
  Weather and calendar lists: scroll content.

Two-finger horizontal scroll:
  Spotify tile: moves across playlists/lyrics/up next or other controls.
  Clock tile: cycles clocks.
  Calendar/weather pills: steps through modes.

Top-left / top-right corners:
  Previous / next track in normal dashboard mode.
  Also skip tracks while the lyrics overlay is open.

Top edge:
  Brightness control in normal dashboard mode.
  Song seek control while the lyrics screen is open.

Right edge:
  Spotify volume in normal dashboard mode and in the lyrics screen. The
  Spotify tile volume column fades away after 4.5 seconds of inactivity and
  reappears when the right edge is used again.

Left edge:
  Local device volume in normal dashboard mode.

Tap:
  Chooses the currently highlighted item.
  Clock tile: activates the current contextual recommendation.
  Guest screen: play/pause.
  Lyrics: closes lyrics.
  Other overlays: defaults to closing or confirming the current surface.

================================================================================
8. DATA FLOWS
================================================================================
SPOTIFY STATE
-------------
  Chromium poll -> GET /api/now (every 2.5 seconds)
      -> server.now()
      -> sp(GET /me/player)
      -> Spotify Web API

The frontend uses a requestAnimationFrame progress renderer that continuously
extrapolates from the last Spotify poll and lightly eases small poll corrections
instead of snapping. The fills use GPU-friendly scaleX transforms. It also uses
local optimistic holds after interactions:

  progress/seek hold
  volume hold
  play/pause hold
  shuffle hold
  repeat hold

The backend coalesces simultaneous GET requests and caches successful results
for 1.25 seconds; failed results are cached for 5 seconds. GET requests never
pile up in unbounded parallel calls.

Spotify actions:
  Browser -> POST /api/<action>
  /api/play, /api/pause, /api/next, /api/prev, /api/volume,
  /api/shuffle, /api/repeat, /api/seek, /api/playlist, /api/playfrom,
  /api/skipto, /api/transfer
  -> server.control()
  -> Spotify Web API

The Spotify Connect device named "Vesper" is provided separately by
soloist.service.

CALENDAR
--------
  calendar ICS URLs in ~/.config/desk-dashboard/calendar.urls
      -> server.cal_loop() refresh thread
      -> recurring_ical_events expansion
      -> /api/calendar?start=...&end=...
      -> frontend month grid, agenda, next-event line, meeting mode,
         morning brief and optional day ribbon

MEETING MODE
------------
The frontend derives the current timed calendar event from agenda data.
When a meeting starts:
  - a meeting banner appears in the Spotify tile
  - music is paused if meeting auto-pause is enabled
  - meeting title and remaining time are shown
When the event ends:
  - music resumes only if Vesper paused it
  - the banner disappears

FOCUS
-----
  User selects duration in Settings or taps contextual advice
      -> focusEnd timestamp saved in localStorage
      -> focus overlay countdown
      -> focused completion toast
      -> focus badge in clock tile

SLEEP
-----
  User selects a sleep duration
      -> sleepEnd and sleepOrigVol saved
      -> during the last 60 seconds Spotify volume fades
      -> at zero music pauses
      -> original Spotify volume restored
      -> sleep badge in clock tile while active

WAKE
----
  User selects a wake time
      -> checkWake() runs every second
      -> if auto-dim is on, brightness ramps in steps
      -> if enabled, music resumes
      -> morning brief is shown

WEATHER
-------
  Frontend -> Open-Meteo forecast API
      -> current temperature, feels-like, humidity, wind, code, rain chance,
         hourly forecast, sunrise and sunset
  Frontend -> Open-Meteo air quality API
      -> current US AQI and PM2.5

Weather is cached by the browser and refreshed every 10 minutes.
The server does not proxy these requests.

LYRICS
------
  Browser -> GET /api/lyrics?title=...&artist=...&duration=...
      -> server.lyrics_lookup()
      -> LRCLIB API
      -> returns synced/plain lyrics
  Browser parses [mm:ss.xx] timestamps and highlights the current line.

Lyrics sync:
  playback position + lyricsOffset
  Positive offset moves matching earlier; negative offset moves matching later.
  Current default: 0.0 seconds (LRCLIB timing already matches playback).
  Adjustable under Settings -> Sound & focus -> Lyrics sync.

The lyric viewport uses a normal block scroller, not flex-centering. The active
line is anchored at about 38% of the lyrics box height so the screen shows
roughly three past lines above and five upcoming lines below. Manual lyric
scrolling temporarily pauses auto-follow for eight seconds.

Lyric progress uses the same underlying #pbar/#ptrack state as the main player.
The top-edge gesture writes to that shared seek control and updates the
top-of-screen lyric progress bar immediately. The right-edge gesture likewise
uses the existing Spotify volume control and reveals a temporary lyric volume
bar.

The one-time storage migration (featureSchema 3) resets the earlier experimental
-1.5/+1.5 offsets to 0.0 for browsers that already saved one of those values.

WIFI QR / GUEST MODE
--------------------
  Guest mode start
      -> frontend GET /api/wifi-credentials
      -> server finds current SSID with wpa_cli
      -> server reads the matching psk from /etc/wpa_supplicant/*.conf
      -> frontend builds WIFI:T:WPA;S:...;P:...;;
      -> bundled qrcode-generator renders an inline SVG locally
  No external QR service is involved.

WIFI JOIN
---------
  Settings -> Network -> Wi-Fi
      -> GET /api/wifi-scan
      -> list of SSIDs
      -> TV keyboard for secured networks
      -> POST /api/wifi-join {ssid, psk}
      -> backend wpa_cli add/select/save
      -> GET /api/wifi-job polling until success/failure

AUDIO OUTPUT
------------
  Browser -> http://127.0.0.1:8081/audio
      -> sink list, default sink, volume
  Browser -> POST /audio/default?name=...
  Browser -> POST /audio/volume?name=...&percent=...
      -> PipeWire/PulseAudio changes

BRIGHTNESS
----------
  Settings -> Display
      -> GET /api/brightness
      -> POST /api/brightness?percent=...
      -> brightnessctl on the backlight device

HEALTH / MAINTENANCE
--------------------
  Settings -> System -> System health
      -> GET /api/health
      -> /proc/loadavg, /proc/meminfo, /proc/uptime
      -> shutil.disk_usage("/")
      -> thermal_zone temperature
      -> ps Chromium process count and RSS
      -> systemctl / systemctl --user service states

  Restart Chromium
      -> POST /api/restart-kiosk
      -> systemctl --user restart vesper-kiosk.service
      -> Chromium reloads the dashboard from localhost

12. PERFORMANCE AND RELIABILITY DESIGN
================================================================================
- Chromium runs through a managed systemd unit, not an unmanaged shell loop.
- Chromium uses GPU rasterization and Wayland, with background services reduced.
- Spotify GET requests are single-flight and briefly cached.
- The main and lyric progress bars are rendered with requestAnimationFrame,
  scaleX transforms and light easing so polling corrections do not cause visible
  jitter. The 250ms interval remains only for synced lyric-line updates.
- Optimistic holds prevent play/pause, shuffle and repeat from flickering back
  during an API round trip.
- The trackpad uses an EventSource channel rather than injecting direct clicks;
  gesture state is handled inside one dedicated script.
- The display's ambient glow uses CSS gradients and album-art sampling, not
  per-frame canvas animation.
- Guest blobs use slow CSS transform animations.
- The lyrics renderer uses CSS transitions and only updates classes/text when
  the active line changes; manual scrolling pauses auto-follow temporarily.
- The smooth clock second hand is driven directly from wall-clock seconds plus
  milliseconds, not from the once-per-second text tick. This prevents the
  second hand from snapping backward at the second boundary.
- The top-edge day ribbon uses simple positioned blocks, no per-frame canvas.
- The Spotify tile volume column uses a CSS opacity transition and a 4.5 second
  inactivity timer; the gesture still works while the column is invisible.
- Daily fun facts are selected from a local hard-coded list based on the day
  of year, so they require no network request.
- The QR code is rendered once per SSID/password pair and cached in page memory.
- The health panel uses low-cost /proc, /sys and ps reads.

================================================================================
16. KNOWN LIMITATIONS AND NOTES
================================================================================
- The Spotify API can be slow. The UI is intentionally optimistic; progress
  bars use requestAnimationFrame with light smoothing to absorb poll timing
  variations.
- Lyrics timing can vary by track/version; use Settings -> Sound & focus ->
  Lyrics sync to move matching earlier or later.
- Album-art colour extraction depends on browser CORS access to the image;
  a deterministic fallback palette is used if extraction is unavailable.
- Wi-Fi QR requires the current network's plaintext PSK to be readable from
  /etc/wpa_supplicant. If it is not available, the guest QR falls back to an
  SSID-only code.
- Guest mode intentionally ignores corner taps to prevent accidental exits.
  Exit with a four-finger swipe up or wait for the guest timer to expire.
- Settings are stored in Chromium local storage, not in the Python server.
- The dashboard server and gesture/audio servers bind only to 127.0.0.1.
  Treat SSH access to the device as the administrative boundary.
- If the dashboard page is updated, restart vesper-kiosk.service so Chromium
  fetches the new HTML. The server sends no-store headers; browser cache is not
  the intended deployment mechanism.
- Keep the backup folders until you are happy with the current state.
